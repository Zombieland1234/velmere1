# External pilot feedback survey

Keep responses attributable to the pilot case, not to unnecessary personal data. Do not tell the participant which answer would create a PASS.

1. Which exact task were you trying to complete?
2. Were you able to identify the target, chain, tier, evidence timestamp and current/withheld state?
3. What did you expect before starting, and what happened?
4. Which result or warning was unclear, missing or too prominent?
5. Could you distinguish reference, stale, withheld, live and executable information?
6. Did the report explain evidence, uncertainty, remediation and retest clearly enough to act safely?
7. Did preview and download appear to be the same artifact? Record the participant-observed filename/time; the operator verifies hashes separately.
8. Did any information appear to belong to another account, reveal private findings, secrets or internal provider topology?
9. Did keyboard, focus, mobile layout, language or assistive technology block the task?
10. If comparing tiers on the same input, what concrete additional decision value did the paid tier provide? “More text” is not sufficient.
11. Did Verify/history accurately distinguish current proof from historical proof after a change or revalidation?
12. What would make you stop using or distrust the product?
13. Classify the outcome: `completed / partially completed / withheld as expected / blocked by defect / unsafe or misleading`.
14. May the operator contact you through the already authorized channel for remediation retest? `YES / NO`.

Operator-only follow-up: map each observation to exact evidence, severity, owner, remediation, retest and disclosure status. Never convert positive sentiment into technical or rights proof.
